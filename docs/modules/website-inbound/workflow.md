# Inbound opportunity workflow

1. Website submissions continue arriving through the existing token-authenticated ingestion API. Account setup forms still route to Finance credit checks.
2. For calls or emails, select **Add opportunity**, enter at least one identity/contact field, select the contact channel, and save. Email is optional; phone-only enquiries are supported. New manual entries initially select the signed-in user as owner, but can be unassigned.
3. Separate source from contact channel: a lead can have source Website and channel Phone. Manual entry cannot impersonate a website form submission.
4. Before manual creation, exact case-insensitive company/email or normalized-phone matches in the same tenant produce a warning. Open a matching record and add a note, or explicitly mark the enquiry as separate and submit again. No automatic merging occurs.
5. Click a company/contact in the queue to open its detail panel. Edit current details and select **Save opportunity**. Website submissions support the same corrections as manual enquiries. An optimistic revision check rejects a stale save instead of overwriting another user's work.
6. Add a note after each interaction. Notes retain their author and timestamp; adding a note does not change the opportunity status or working details.
7. Set an owner, next action, and follow-up date for active work. These are recommended operating practices, not mandatory save gates, so incomplete historical submissions remain editable.
8. Approved Microsoft 365 owner mailboxes synchronize Inbox and Sent Items hourly. **Sync mail now** provides the same bounded read on demand. A message links by an already-linked Microsoft conversation or one exact opportunity email. When the same email belongs to several open opportunities, choose the correct record in **Email matching needs review**.
9. Assign the opportunity to a mail-enabled owner before drafting. **Prepare suggested reply** uses the linked conversation and enquiry facts; if live AI drafting is unavailable, a clearly labelled safe template is produced instead. The suggestion does not change status, next action, or follow-up date.
10. The assigned owner reviews the recipient, subject, and body and selects **Approve exact email & send**. The server rechecks tenant, owner, approved mailbox, current recipient, open status, and newer correspondence before calling Microsoft Graph. Other users cannot send from the owner's mailbox.
11. After the first outbound email, the conversation mailbox is fixed. Reassignment requires the new owner to accept the visible mailbox handoff. Earlier messages remain attributed to their original mailbox.
12. Use Due today and Overdue in Toronto time to work the follow-up queue. The draft can recommend a next action and date, but the employee decides whether to save them. Automated customer follow-ups remain disabled during the pilot.

The original form payload can be expanded below the activity history. Selecting a closed status can remove a row from the open queue while its selected detail remains visible. Explicit status filters override the quick view's lifecycle restriction; owner/date filters still apply. Quick-view links clear status and owner overrides.
